# 报表中心设计说明 (Design Spec)

## 1. 目标与范围
- **目标**：克隆产品原型中的“报表中心”页面，将当前前端的占位静态页替换为完整可用版。
- **范围**：涵盖顶部 4 个统计卡片、分类 Tab 与搜索、中部 6 个报表模板卡、底部最近生成记录表格。
- **核心原则**：
  - 数据驱动：前端严禁硬编码业务数据、禁止 Mock、禁止伪造统计结果。
  - 视觉收敛：布局、间距、按钮状态、卡片文案（含报表名称、类别等）必须一字不差地照抄原型。
  - 域隔离：在后端建立独立的 `/iot/factory/report` 域和专用数据库表，不与其他业务表强耦合，避免现有口径影响原型展示。

## 2. 架构设计

### 2.1 数据库模型
新增两张主表（存放于 `ruoyi-vue-pro` 数据库中）：
1. **`iot_factory_report_template` (报表模板表)**
   - `id` (主键)
   - `template_code` (模板编码)
   - `template_name` (模板名称，如“日报表”)
   - `template_category` (类别，如“日分类”)
   - `template_desc` (说明)
   - `sort_no` (排序)
   - `status` (状态)
   - `cron_type` (调度类型，预留)
   - `tenant_id`, `creator`, `create_time`, `updater`, `update_time`, `deleted`

2. **`iot_factory_report_record` (报表生成记录表)**
   - `id` (主键)
   - `template_id` (关联模板)
   - `report_name` (报表实例名称，如“日报表-20240115”)
   - `report_category` (报表类别，用于冗余和筛选)
   - `status` (状态：PENDING/RUNNING/SUCCESS/FAILED)
   - `generated_at` (实际生成时间)
   - `biz_date` (业务日期)
   - `file_name` (文件名)
   - `file_url` (文件地址)
   - `operator_name` (操作人)
   - `tenant_id`, `creator`, `create_time`, `updater`, `update_time`, `deleted`

### 2.2 后端接口
挂载在 `/iot/factory/report/**` 下，提供 4 个主要接口：
- `GET /dashboard`: 返回首屏全量聚合数据（4个统计值、分类列表、模板卡片列表、最近记录列表）。
- `POST /generate`: 触发报表真实生成，落库记录表并返回生成状态。
- `GET /preview`: 根据记录 ID 获取预览地址或内容。
- `GET /download`: 根据记录 ID 下载报表文件。

### 2.3 前端结构
- **页面入口**：`yudao-ui-admin-vue3/src/views/factory/report/index.vue`
- **请求定义**：`yudao-ui-admin-vue3/src/api/factory/report.ts`
- **组件结构**：
  - 沿用 `FactoryDashboardShell` 壳层。
  - 内部实现：顶部统计网格 -> 筛选操作区 -> 模板卡片网格 -> 最近记录表格。

## 3. 详细交互与数据映射

### 3.1 顶部统计区
- `报表总数`：计算 `iot_factory_report_template` 中启用的模板数。
- `已生成`：计算 `iot_factory_report_record` 中状态为 SUCCESS 的总数。
- `今日生成`：计算 `iot_factory_report_record` 中 `generated_at` 为当天的成功数。
- `待生成`：由后端计算当天应生成但未生成的模板数量。
- **注意**：前端不写死 `6 / 128 / 6 / 2`，全部由接口返回。

### 3.2 模板卡片区
- 共 6 个卡片，数据来源于 `iot_factory_report_template`。
- 按钮状态控制：
  - **预览**：接口返回该模板最新成功记录且具备预览内容时启用。
  - **生成**：模板启用时均可点击，点击后按钮 Loading 并请求 `/generate`，成功后刷新整个 Dashboard 数据。
  - **下载**：接口返回该模板最新成功记录且具备文件时启用。

### 3.3 最近生成表格区
- 数据来源于 `iot_factory_report_record`。
- 筛选：与上方的“分类 Tab”和“搜索框”联动，前端只渲染，数据筛选可由后端一并处理（首屏全量后前端过滤，或每次切换重新拉取，视数据量而定，首选前者以提升体验）。

## 4. 异常处理与验证
- **错误提示**：生成失败或下载失败时，利用 ElMessage 提示后端返回的真实错误信息。
- **响应式布局**：窄屏下顶部 4 卡片不允许折行，采用容器内横向滚动（`overflow-x: auto` + `white-space: nowrap`）。
- **补数策略**：通过 `ch_mysql` MCP 在开发库中批量插入 6 条模板数据和 30+ 条记录数据，覆盖成功、失败以及跨越数天的时间分布，确保统计数字和表格都能跑通。补数前采用“清空对应租户旧数据再插入”的幂等策略。

## 5. 里程碑
1. 数据库建表与后端基础代码（Controller, Service, Mapper）。
2. MCP 自动补全测试数据。
3. 前端类型定义与 API 对接。
4. 前端 UI 重构（统计卡、模板卡、表格）与原型 1:1 对齐。
5. 前后端联调（生成、预览、下载链路）。
