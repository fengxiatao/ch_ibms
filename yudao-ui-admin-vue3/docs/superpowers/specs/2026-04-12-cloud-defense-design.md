# 立体化云防高保真克隆与真实数据接入设计

## 1. 目标

- 以用户提供的“立体化云防”原型截图为本期页面唯一视觉对齐基准，高保真重建首屏布局、视觉层级和深色科技风格
- 将当前占位页 `src/views/factory/cloudDefense/index.vue` 升级为真实业务工作台，不再复用通用承接页展示说明文案
- 页面所有展示数据必须来自后端接口与数据库，不使用硬编码业务值、不使用 mock 数据、不使用前端伪造统计结果
- 若开发库缺少测试数据，则通过 MCP 直接插入合理测试数据，保证页面联调、验收与后续回归均基于真实数据库记录
- 在保持当前项目动态路由、暗色主题、Vue3 + TypeScript 规范的前提下，完成“页面高保真克隆 + 接口补齐 + 表结构补齐”的一体化落地

## 2. 范围

### 2.1 本期包含

- 重构 `src/views/factory/cloudDefense/index.vue`
- 按原型重建顶部指标区、模式切换区、中部布防态势区、右侧云防设备区、底部防区管理区
- 前端按模块拆分组件，形成可扩展的立体化云防页面架构
- 后端新增立体化云防聚合接口与管理接口
- 在现有安防、视频、空间、防区底座之上补充页面编排所需表结构
- 所有页面展示数据从后端数据库查询获得
- 缺失联调数据时，通过 MCP 直接向开发库插入合理测试数据

### 2.2 本期不包含

- 将“区域入侵、行为分析、轨迹追踪、智能巡检、安全态势”五个模式全部做成完整独立业务页
- 构造假的告警态势、假视频流、假设备在线结果或假安全评分
- 引入 iframe 承接静态原型页
- 对智慧工厂其他一级业务页面做同步重构

## 3. 当前现状与承接关系

### 3.1 当前页面现状

- 当前入口页：`src/views/factory/cloudDefense/index.vue`
- 当前页面仅复用 `FactoryModuleLanding`，属于占位式承接页
- 当前内容包含状态说明、接入原则和规划范围，未承载真实云防业务视图
- 当前实现与原型差距集中在首屏工作台结构缺失，而不是细节样式微调

### 3.2 可复用的现有能力

- 空间能力：`ibms_space`
- 通道能力：`ibms_channel`
- 设备能力：`ibms_device`
- 告警主机 / 分区 / 防区能力：现有 `iot_alarm_host`、`iot_alarm_partition`、`iot_alarm_zone`
- 视频与回放能力：现有视频通道、NVR、回放接口与播放器组件
- 实时推送能力：现有告警 WebSocket 与设备状态推送链路

### 3.3 本期承接原则

- 继续沿用后端动态菜单与动态路由，不新增前端静态菜单
- 复用现有空间、设备、通道、告警、防区、视频底座，不重复造基础能力
- 补齐的是“立体化云防页面编排层”和“页面专属聚合接口”，不是推翻现有底座

## 4. 页面结构设计

### 4.1 顶部指标区

- 指标数量保持 4 个，与原型一致
- 指标内容固定为：防区状态、在线设备、今日入侵告警、安全态势评分
- 指标区只展示聚合结果，不在前端拼装多路统计值
- 所有指标统一来自总览聚合接口

### 4.2 模式切换区

- 首屏保留 6 个模式入口：周界防护、区域入侵、行为分析、轨迹追踪、智能巡检、安全态势
- 第一阶段仅将“周界防护”做成完整真实工作台
- 其余模式保留可切换结构与真实空态承接，不伪造业务图表和假结果
- 模式配置、排序、是否启用由后端接口控制

### 4.3 中部布防态势区

- 中部区域按原型重建为“周界防护态势图”
- 第一阶段使用程序化 SVG / DOM 绘制外框、边界线、防护点、区域块、图例和状态高亮
- 主画布中的每个区域和点位都绑定真实主键，支持后续联动和定位
- 画布不使用静态截图当作真实交互区域

### 4.4 右侧云防设备区

- 展示云防设备列表，字段建议统一为：设备名、设备类型、所在区域、在线状态、能力标签
- 列表按当前模式和当前选中区域联动筛选
- 设备状态来自真实设备 / 通道 / 防区关联数据

### 4.5 底部防区管理区

- 展示防区卡片列表，字段建议统一为：防区名称、设备数、布防状态、告警数、健康状态
- 保留全局设防入口与单防区动作位
- 若本期未闭环真实下发布防动作，则按钮仅展示可扩展动作位，不伪造成功反馈

## 5. 组件拆分设计

- `index.vue`：负责页面数据获取、状态管理、事件编排与组件装配
- `CloudDefenseMetricCards.vue`：承接顶部 KPI 区
- `CloudDefenseModeTabs.vue`：承接模式切换区
- `CloudDefenseTopologyCanvas.vue`：承接中部态势图、区域高亮、点位联动和图例
- `CloudDefenseDeviceList.vue`：承接右侧云防设备区
- `CloudDefenseZoneGrid.vue`：承接底部防区管理区
- `CloudDefenseEmptyState.vue`：承接非周界模式和真实空态的统一展示

## 6. 数据模型设计

### 6.1 继续复用的基础表

- `ibms_space`
- `ibms_channel`
- `ibms_device`
- `iot_alarm_host`
- `iot_alarm_partition`
- `iot_alarm_zone`
- `iot_device_event_log`

### 6.2 建议新增的页面编排表

#### 6.2.1 `iot_cloud_defense_area`

- 用于定义页面中的防护区域
- 关键字段：`id`、`name`、`code`、`space_id`、`area_type`、`sort`、`enabled`

#### 6.2.2 `iot_cloud_defense_point`

- 用于定义主画布中的布防点、感知点、设备点
- 关键字段：`id`、`area_id`、`device_id`、`channel_id`、`point_code`、`point_name`、`point_type`、`x_ratio`、`y_ratio`、`armed_status`

#### 6.2.3 `iot_cloud_defense_mode`

- 用于定义页面顶部模式切换配置
- 关键字段：`id`、`mode_code`、`mode_name`、`enabled`、`sort`

#### 6.2.4 `iot_cloud_defense_area_device_rel`

- 用于建立区域与设备的映射关系
- 关键字段：`id`、`area_id`、`device_id`、`channel_id`、`sort`

#### 6.2.5 `iot_cloud_defense_score_log`

- 用于记录安全态势评分快照
- 关键字段：`id`、`score`、`score_level`、`score_time`、`remark`

### 6.3 新增表的意义

- 现有基础表更偏底层台账和告警域
- 原型页面需要承载“区域显示位置、点位坐标、模式编排、区域设备映射、评分快照”这类页面语义
- 这些信息若继续塞入已有表的扩展字段，后续会增加维护成本和隐式耦合

## 7. 接口设计

### 7.1 页面聚合接口

- `GET /iot/cloud-defense/overview`
- 返回顶部 KPI、模式列表、当前模式、画布区域、画布点位、设备列表、防区列表和评分摘要
- 首屏只依赖这一组核心聚合接口完成渲染

### 7.2 二级查询接口

- `GET /iot/cloud-defense/mode/list`
- `GET /iot/cloud-defense/area/{id}`
- `GET /iot/cloud-defense/device/page`
- `GET /iot/cloud-defense/zone/page`
- `GET /iot/cloud-defense/score/latest`

### 7.3 管理接口

- `POST /iot/cloud-defense/area/create`
- `PUT /iot/cloud-defense/area/update`
- `POST /iot/cloud-defense/point/create`
- `PUT /iot/cloud-defense/point/update`
- `POST /iot/cloud-defense/area-device-rel/create`

### 7.4 接口策略

- 页面首屏统一走 `overview` 聚合接口
- 详情、分页、配置类数据在二级接口按需加载
- 前端不自行并发拼接多个零散接口作为首屏主数据源

## 8. 数据来源与测试数据原则

### 8.1 数据来源原则

- 前端页面中出现的所有指标、设备状态、防区状态、态势评分和区域点位必须来源于后端接口
- 后端接口查询结果必须来源于数据库记录
- 禁止在前端写死业务统计值、设备状态值、防区状态值和示意列表
- 禁止使用 mock 文件、内联假数据、随机生成演示数据作为验收依据

### 8.2 测试数据策略

- 若现有开发库已具备可用数据，优先直接复用
- 若现有开发库缺少立体化云防所需区域、点位、模式、评分或映射数据，则通过 MCP 直接插入合理测试数据
- 插入的数据必须满足真实业务关系，至少能支撑：
- 顶部 4 个指标可查询
- 中部至少 3 个区域、多个点位可联动
- 右侧至少存在多条设备记录，且在线 / 离线状态可区分
- 底部至少存在多条防区记录，且布防 / 未布防状态可区分

### 8.3 测试数据约束

- 测试数据需要与已有空间、设备、通道、主机、防区记录保持外键或业务关联合理
- 数据命名采用业务化命名，不使用 `test1`、`demo1` 这类低可读命名
- 后续若需要回收测试数据，需保证具备明确数据标识

## 9. 页面状态流转与交互设计

### 9.1 首屏加载

- 页面进入后先请求 `overview`
- 聚合结果统一分发给顶部、中部、右侧和底部模块
- 若用户继续查看某区域详情，再按需加载二级接口

### 9.2 模式切换

- 切换到“周界防护”时，加载真实工作台内容
- 切换到其他模式时，仅展示真实空态承接，不补假图表

### 9.3 区域联动

- 点击主画布区域后，中部区域高亮
- 右侧设备区切换为当前区域相关设备
- 底部防区区优先显示当前区域关联防区

### 9.4 点位联动

- 点击布防点后，主画布高亮当前点位
- 右侧设备列表滚动并定位到对应设备
- 若存在视频通道，预留跳转视频融合页或打开实时预览入口

### 9.5 状态刷新

- 第一阶段采用“首次加载 + 手动刷新 + WebSocket 增量刷新”
- 不采用高频轮询替代真实推送

## 10. 异常处理与降级策略

### 10.1 页面级异常

- `overview` 聚合接口失败时，展示页面级错误态与重试按钮
- 不允许接口失败后整页白屏且无反馈

### 10.2 模块级异常

- 二级接口失败时，仅当前模块进入错误态
- 其他已成功模块继续保持可读和可操作

### 10.3 空态处理

- 真实无数据时展示统一空态
- 空态文案使用“暂无接入数据 / 待配置”语义
- 不用虚构列表填满版面

### 10.4 异步动作处理

- 如本期接入设防 / 撤防动作，需包含 loading、成功反馈和失败反馈
- 若后端动作是异步下发，前端显示“指令已发送，状态同步中”，等待状态回刷

## 11. 实施原则

- 先完成页面骨架和组件拆分，再接入真实接口与数据库数据
- 尽量复用现有空间、设备、告警、防区、视频能力，不重复建设底座
- 页面样式贴近原型，但必须服从项目暗色主题规范
- 周界防护模式优先完整落地，其余模式保持扩展位与真实空态

## 12. 风险与约束

- 原型中的中心态势图为视觉表达，当前系统未必已有完全一致的空间可视化模型，需要通过程序化绘制实现贴近
- 若现有库中缺少关联完整的空间、设备、防区关系，需要同步补数才能完成联调
- 部分模式当前仅能提供外壳与空态承接，不能为了“看起来完整”补假数据
- 页面为深色业务工作台，不应回退成普通后台卡片页

## 13. 验收标准

- 页面首屏结构与原型主布局高度一致
- 顶部 4 指标、模式切换、中部态势图、右侧设备区、底部防区区均完成真实业务承接
- 页面所有展示数据来自后端接口和数据库记录
- 若缺数据，已通过 MCP 向开发库插入合理测试数据并完成联调
- 点击区域、点位能够驱动设备区与防区区联动
- 非周界模式不伪造数据，使用真实空态承接
- 页面继续通过 Vue3 原生实现，不引入 iframe
