# 2026-04-13 业务协同四大域工作台（4 Tab）设计规格

## 背景与目标

产品原型提交了“业务协同”原型页面，要求在当前项目中按既有智慧工厂风格克隆落地，并满足：

- 页面包含 4 个一级 Tab：生产协同、能源管理、设备管理、碳资产
- 每个一级 Tab 下包含原型对应的二级 Tab（需完整克隆）
- 所有页面数据必须来自后端接口与数据库
- 前端禁止硬编码业务数据、禁止 Mock、禁止伪造统计结果
- 若开发库缺测试数据，通过 MCP 直接补充合理测试数据

本规格用于指导前后端实现与联调验收。

## 非目标（本次不做）

- 不引入 iframe 嵌入静态原型页面；必须以 Vue3 组件实现
- 不引入完整 ERP/MES 或 BPM 引擎迁移（当前仓库未装配完整业务模块），本次以 `iot/factory` 领域内独立建模实现
- 不承诺生产现场“真实采集链路”已打通；本次先保证数据模型、接口、页面可操作闭环与可验证的数据一致性

## 页面信息架构

### 路由与入口

- 入口保持为现有智慧工厂菜单：`/factory/collaboration`
- 页面实现位置保持：`src/views/factory/collaboration/index.vue`（由占位页升级为正式页面）
- 页面标题：业务协同
- 页面副标题：建议保留原型风格描述（由产品确认后固化）

### 一级 Tab（固定 4 个）

1. 生产协同
2. 能源管理
3. 设备管理
4. 碳资产

一级 Tab 在同一页面内切换，不拆成 4 个独立路由页面（避免割裂协同场景，便于统一筛选与联动）。

### 二级 Tab（按原型完整克隆）

- 生产协同：生产计划、批次追踪
- 能源管理：综合概览、电力、水、气
- 设备管理：设备列表、维保计划
- 碳资产：Carbon Overview、Emission Sources、Carbon Trading

### 通用布局骨架（每个二级 Tab 适用）

建议保持一致的三层结构以适配原型与可扩展性：

- 顶部指标卡区域（KPI cards）
- 中部主工作区（表格 / 趋势图 / 排行 / 详情区）
- 底部补充区/联动区（告警联动、建议卡片、辅助统计等）

## 数据与交互约束（强约束）

### 强制真实数据

- 禁止在前端写死业务统计数字、排行结果、趋势曲线数据
- 允许的前端“静态内容”仅限：
  - 固定 Tab 名称、列标题、字段标签等 UI 文本
  - 非业务统计的常量（如分页默认 pageSize、颜色映射、单位格式化）
- 空态必须为“真实空态”：当数据库无数据时展示“暂无数据”，不得回退为伪造默认数据

### 搜索与筛选

- 顶部全局搜索框与日期选择必须真实影响后端查询
- 前端不得在拿到后端分页数据后再做“业务口径筛选”来伪造统计一致性
- 一级/二级 Tab 切换时：
  - 重置分页到第 1 页
  - 保留公共筛选条件（搜索词、日期范围、区域等）

### 详情与动作闭环

每个一级 Tab 必须至少包含可验证的写操作闭环（创建/更新/处理等），并满足：

- 写操作通过真实后端接口落库
- 写操作完成后刷新对应区块数据，确保指标卡/列表/详情一致
- 写操作失败时展示后端返回错误原因（不吞错、不转成“成功”）

## 后端领域建模与接口拆分

### 领域落点

统一在 `iot/factory` 体系下新增“业务协同”领域：

- Controller 建议前缀：`/iot/factory/collaboration/**`
- 内部按 4 个子域拆分：`production`、`energy`、`device`、`carbon`

目标是：领域语义清晰、接口边界可维护、避免把所有内容塞进一个“万能表”。

### 数据建模原则

- 业务事实表为主：可追溯、可复算
- 统计结果不做“唯一事实来源”：允许做按日/按小时汇总表提升性能，但必须可由事实表复算校验
- 所有 KPI 口径在后端统一定义并实现，前端仅展示

### 子域表建议（最小可行集）

#### 生产协同（production）

- 生产计划表：计划编号、产品、批次号、计划数量、负责人、开始/结束时间、状态、进度、产线/区域
- 批次追踪表：批次当前工序、位置、产量、良率、状态、更新时间
- 生产异常事件表：异常类型、严重级别、关联计划/批次、发生位置、责任人、处理状态
- 生产操作记录表：计划创建、派工、开工、暂停、完工、异常处理等动作留痕

#### 能源管理（energy）

- 能源采集点表：电/水/气仪表、关联设备、所属区域、单位、状态
- 能源时序读数表：采集点、时间、数值、增量、来源
- 节能建议/诊断表：建议类型、关联区域/设备、触发规则、建议内容、状态

#### 设备管理（device）

- 设备台账表：设备编码、名称、类别、型号、区域、状态、效率、在线状态
- 设备状态快照表：运行/告警/在线状态、效率等
- 维保计划表：周期、下次维保时间、负责人、状态
- 维保工单表：由计划生成或手工创建，记录执行、完成、异常、验收

#### 碳资产（carbon）

- 碳排核算表：按日/月记录排放量、口径、关联主体
- 排放源表：排放源定义与排放因子
- 碳目标表：年度/月度目标、责任主体、目标值、口径
- 碳交易表：配额、买入、卖出、结余、时间、状态

### API 拆分建议

为保持页面骨架稳定、接口清晰，建议每个二级 Tab 至少拆成：

- 概览接口：返回 `summary`（指标卡）+ `content`（趋势/排行/主内容必要字段）+ `extra`（联动区）
- 分页列表接口：表格/列表型数据（支持搜索、日期、状态、区域等过滤）
- 详情接口：点击行/卡片后获取详情与时间线
- 写操作接口：创建/更新/处理/登记等
- 导出接口（如原型存在导出）：返回真实导出文件

### KPI 口径（由后端定义并实现）

- 生产协同：今日生产批次、完成率、待生产批次、生产效率
- 能源管理：今日用电、今日用水、今日用气、同比节能
- 设备管理：设备总数、在线设备、故障设备、维保中
- 碳资产：本月碳排、单位排放、年度目标、目标完成率

## 关键联动规则

- 生产协同：
  - 生产计划表行点击：打开详情抽屉/右侧详情区，联动展示关联批次与异常
  - 异常卡片点击：反查关联计划/批次并跳转/定位
- 能源管理：
  - 综合/电/水/气共用筛选与日期，切换只改变聚合维度与指标口径
- 设备管理：
  - 设备卡片点击：右侧详情实时刷新
  - 切到维保计划：保留设备筛选条件（若原型如此）
- 碳资产：
  - 总览/排放源/交易共享日期范围与责任主体筛选

## 错误处理与空态策略

- 区块级容错：某区块接口失败，仅该区块展示错误态，不影响同页其他区块
- 空态为真实空态：无数据时展示“暂无”，禁止伪造默认曲线/排行
- 写操作失败展示后端原因：例如状态冲突、余额不足、参数校验失败等

## 权限与审计

- 页面入口权限沿用：`factory:collaboration`
- 动作级权限建议细分到子域与动作（示例）：
  - `factory:collaboration:production:create`
  - `factory:collaboration:device:maintain`
  - `factory:collaboration:carbon:trade:create`
- 所有写操作需要审计留痕（操作记录/工单记录/交易记录等）

## 测试数据策略（开发库）

- 若开发库缺数据，通过 MCP 直接插入满足真实关系的测试数据
- 数据必须覆盖：
  - 4 个一级 Tab 都能展示指标卡、主内容与空态切换
  - 至少每个一级 Tab 1 条可操作闭环链路可验证
- 禁止通过前端 hardcode/Mock 代替开发库数据

## 实施顺序（建议）

1. 后端：新增表结构与迁移 SQL、Mapper、Service、Controller
2. 数据：用 MCP 往开发库补充测试数据（确保四大域可展示且有关联）
3. 前端：升级 `factory/collaboration` 为正式页，先落统一骨架与一级/二级 Tab 切换
4. 前端：逐个二级 Tab 接入真实接口与写操作闭环
5. 联调：校验“指标卡-主内容-详情/动作-刷新一致性”
6. 质量：对改动文件做 VS Code 诊断与 ESLint/局部校验，避免全量类型检查内存风险

## 验收清单

- 页面：一个入口页面内包含 4 个一级 Tab，且每个一级 Tab 下的二级 Tab 与原型一致
- 数据：所有指标卡/列表/趋势/排行均来自真实后端 API 与数据库
- 约束：前端无业务数据硬编码、无 Mock、无伪造统计结果
- 闭环：每个一级 Tab 至少 1 个写操作可用，且落库可复查、刷新后一致
- 空态：无数据时显示真实空态，不回填默认假数据
